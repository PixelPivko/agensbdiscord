# Итоговый отчёт — Агент Службы Безопасности

Дата: 4 октября 2026, Europe/Moscow. Проект самостоятельный, Python 3.12.
Production Discord не подключался; токен не предоставлен и в поставке отсутствует.

## Что реализовано

1. Разделение на `cogs/`, `services/`, `config/`, `tests/`, `deploy/`, `data/`.
   Полное дерево проекта и описание модулей — в README.
2. Runtime: discord.py **2.7.1**, aiosqlite **0.22.1**, PyYAML **6.0.3**, python-dotenv **1.2.4**.
   Прямые и транзитивные версии зафиксированы в `requirements.lock`; тестовые — в `requirements-dev.lock`.
3. Токен читается из `.env` (`DISCORD_TOKEN`), есть `.env.example` и `.gitignore`.
   Структурированные JSON-логи не сериализуют DM/HTTP exception payload и редактируют известный токен.
4. **17 верхнеуровневых slash-команд/групп, 23 конечные команды.**
   `level`, `leaderboard`, `warn`, `warnings`, `unwarn`, `clearwarns`, `timeout`, `untimeout`, `kick`, `ban`,
   `unban`, `purge`, `userinfo`, `modlog`; группы `verification` (reset/resend/panel), `xp` (add/remove/set),
   `levels` (set/sync/syncall). Полные сигнатуры — в README.
5. Индивидуальная captcha с кнопкой и modal: 1–10, +/−/×, 600 секунд, 5 попыток, nonce,
   проверка владельца, одноразовый ответ, защита от повторного использования старого modal.
   Состояние и число попыток сохраняются в SQLite, views восстанавливаются после перезапуска.
6. При вступлении — timeout 7 дней. Успешная captcha сразу снимает ограничение проверки.
   Отдельное наказание модератора сохраняется. Незавершённое снятие timeout повторяется фоновым восстановлением.
7. Семь join roles из ТЗ выдаются только после успешной проверки. Verified сохраняется для повторного входа.
   Недовыданные роли восстанавливаются автоматически; reset удаляет управляемые роли и требует новую captcha.
8. `AntiProfanitySystem`: JSON blacklist/whitelist, границы слов, нормализация и простые разделители,
   configurable исключения. Новые и изменённые сообщения проверяются; нарушение удаляется, создаётся warn,
   уведомление и modlog. Staff автоматически не освобождается от фильтра.
9. SQLite warnings с source/active/guild_id; пороги 3/5/7/10 настраиваются. Автобан выключен.
   Сотрудники определяются по роли, Administrator или owner. Проверяются иерархия и права бота.
10. `ActivityLevelSystem`: 1–3 XP, cooldown 60 секунд, минимальная длина, запрет наград за команды,
    повторные сообщения и spam; транзакции защищают от конкурентного начисления.
    Удаление сообщения отменяет XP в пределах срока хранения квитанций.
11. Уровни 0–1000, формула `50 × L × (L+1)`, пять точных пар ролей из ТЗ.
    Старая пара удаляется перед новой, остальные роли сохраняются. Startup/периодическая/ручная сверка,
    последовательная обработка с паузами и штатным rate-limit handling библиотеки.
12. SQLite: `data/security_agent.db`, создаётся при запуске. Все пользовательские ключи и запросы
    разделены по `guild_id`. WAL, сериализованные транзакции, persistent audit/outbox.
13. Тесты и статические проверки: результаты ниже.
14. README содержит порядок установки Ubuntu 24.04, создание пользователя, venv, установку зависимостей,
    заполнение config/токена, `--check`, `--preflight`, обычный запуск и проверки тестовым аккаунтом.
15. Готовый `deploy/security-agent.service`: отдельный пользователь, автоперезапуск при ошибке,
    journald, ограничение записи в `data`, EnvironmentFile, graceful SIGTERM.

## Уточнения реализации и пределы локальной проверки

- `/level set` назван `/levels set`: сохранена отдельная команда просмотра `/level`, что соответствует
  модели команд Discord.
- Fallback при закрытых DM предлагает открыть DM и выполнить staff `/verification resend`.
  Активный timeout ограничивает публичное взаимодействие; бот не снимает его до captcha.
- В config остаются **три неизвестных ID**: сервер, verification channel и modlog channel. Они равны 0,
  поэтому сетевой запуск намеренно блокируется до заполнения. Все role IDs из ТЗ уже внесены.
- Действительные permissions/hierarchy/intents можно подтвердить только `--preflight` с токеном пользователя
  и последующим прогоном на тестовом сервере. Локальные mocks не заменяют эту проверку.
- Первый запуск не ограничивает массово существующих участников. Для них предусмотрен ручной reset;
  автоматический XP доступен только после verification.
- Одновременно запускается один процесс на одну БД. Discord-действия не могут составлять единую транзакцию
  с SQLite: восстановление делает роли и verification согласованными после сбоя. Неопределённое выполнение
  опасной escalation требует проверки сотрудником, а не автоматического повторения бана.
- Проверка доступа через роли/каналы нужна и при остановленном боте: Discord timeout конечен.
- Запоздалое удаление сообщения отменяет награду, если событие получено и квитанция не старше 30 дней.
  Во время полного отключения бота события удаления могут быть потеряны.
- Словарь фильтра — начальный, точные формы расширяются администратором; это не универсальная модель русского языка.

Результат поставки: исходники, config, словари, тесты, lock-файлы, README и systemd unit.
В архиве нет токена, рабочей БД, виртуального окружения, Python cache или скрытых административных команд.
